01

AI를 활용한 PO의 일하는 방식

AI를 코드 보조 도구가 아니라 PM/PO 실무의 지렛대로 씁니다. 정책·요구사항·QA 문서화부터 동작하는 프로토타입까지 직접 만들어, 의사결정 속도와 딜리버리 폭을 함께 끌어올립니다.

Decision

결정에는 근거를 남긴다

문제 → 근본원인 → 해결 → 기대임팩트 순서로 사고하고, 상급자 제안도 KPI로 재검증한 뒤 대안을 제시합니다.

Stakeholders

3자 이해관계자 렌즈

병원·기업·임직원의 이해가 충돌하는 지점을 규제·법무·정산까지 고려해 설계합니다.

Traceability

정본 하나로 추적한다

정책 → SRS → 개발 TASK → QA → 지표를 단일 허브에서 연결(RTM)해 요구사항 누락과 역추적 비용을 줄입니다.

AI Pipeline

AI로 기획-디자인을 잇는다

노션 정책을 스토리보드·Token JSON으로 변환해 Figma로 넘기는 파이프라인을 직접 설계했습니다.

정책→SRS→개발 TASK→QA 시나리오→Cross-surface E2E→지표(Amplitude)

대표 프로젝트

🎟 Case File — B2B2C

쿠폰팩 · 기업 임직원 의료 베네핏 시스템

Role
Lead Product Owner
Scope
App · CMS · 병원 3서피스
Domain
B2B2C 헬스케어 / 복지몰
문제Situation

기업이 임직원 복지로 의료 할인을 주고 싶어도, 병원 예약·결제·정산과 연결된 쿠폰 발급·사용·환불·정산 체계가 없었다. 임직원(앱)·운영(CMS)·병원(관리자) 세 서피스가 하나의 쿠폰 라이프사이클을 공유해야 하는 문제.

역할Task

여러 혜택안을 비교해 ‘쿠폰팩 단일안’ 채택을 이끈 의사결정부터, 정책 정의 → SRS → 개발 TASK → QA → 지표까지 프로덕트 전 과정 오너십을 맡았다.

과정Action
영역핵심 의사결정 · 실행
사용 규칙1인 1회 10장 발급, 180일 유효, 1결제 1쿠폰, 예약 시 최대혜택 자동매칭
예외 처리병원 업셀 시 쿠폰 재추천 · 취소 시 쿠폰/유효기간 원복 · 제휴 종료 시 전 임직원 즉시 차단
규제 대응동의 3종 버전 스냅샷 관리, 주요 개정 시 재동의 트리거
기획-디자인정책은 노션 정본, 디자인은 노션 → Claude 스토리보드 → Token JSON → Figma 파이프라인 확립
운영 준비알림톡 13종 템플릿 설계·심사, 병원관리자·앱 사용자 매뉴얼 작성
결과Result
Deliverables — 증거
SRS 요구사항 정의서 F1·F2 개발 TASK 정의서 UM·BO·PA QA 통합테스트 시나리오 Cross-surface E2E BO·UM·PA SRS↔TASK↔QA RTM Amplitude 이벤트 퍼널 알림톡 13종 운영 매뉴얼 2종
AI Leverage PO가 AI로 직접 수행한 일
노션 정책 정본→Claude 스토리보드→Token JSON→Figma
  • 기획→디자인 변환을 AI 파이프라인으로 자동화 — 정책 텍스트를 스토리보드·디자인 토큰으로 바꿔 디자인 왕복 비용을 줄임
  • SRS·개발 TASK·QA 시나리오·RTM·알림톡 13종을 AI 워크플로우로 생성·정합성 관리
  • Cross-surface E2E QA를 AI + Playwright로 자동화해 회귀 검증을 반복 가능하게
Reflection
크로스서피스 프로덕트는 취소·업셀·종료 같은 엣지케이스의 데이터 정합성이 승부처였다. E2E를 해피패스가 아닌 네거티브 케이스 중심으로 설계해 결함을 개발 초기에 잡을 수 있었다.
🌐 Case File — Global

SafeDoc Global · 미국 환자 대상 한국 의료관광 사이트

Role
PO · 요구사항 · Admin UX · 구축판단
Scope
글로벌 브랜드 사이트 + Admin
Stack
React · SSG · EN/KO
문제Situation

미국 보험 환자를 한국 의료(성형·피부·정형·회복)로 유치하는 글로벌 브랜드 사이트가 필요했다. 핵심 KPI는 SEO·GEO 검색 노출. 사내에선 “SEO에 유리하니 WordPress로 만들자”는 제안이 있었다.

과정Action
이슈판단 · 실행
구축 방식WordPress 제안을 그대로 수용하지 않고 운영·확장·측정 관점에서 자체 구축(React+SSG)으로 판단 — SEO는 사전렌더+구조화데이터로 대응
콘텐츠 운영비개발자가 코드 없이 시술·가격·제휴병원을 라이브 편집하는 Admin 설계 (12개 콘텐츠 컬렉션)
배포·데이터Admin 변경 → 커밋 → 자동 배포 파이프라인, Admin ↔ DB 연결
성과 측정노출률·인입률·유입수 계측을 Admin 대시보드에 노출하도록 요구사항 정의
결과Result

동작하는 라이브 사이트 + Admin을 제공했고, 비개발 운영자가 콘텐츠를 직접 수정해 업데이트 리드타임을 단축했다. SEO 구조화데이터·사이트맵 자동화로 검색 노출 기반을 확보했다.

AI Leverage PO가 AI로 직접 수행한 일
요구사항→AI 구현(Claude Code)→동작하는 사이트 + Admin→의사결정·설득
  • 비개발 PO가 AI로 React+SSG 사이트를 직접 프로토타이핑 — "문서가 아닌 동작하는 제품"으로 방향을 증명하고 설득
  • 비개발자용 Admin·SEO 구조화데이터·EN/KO 다국어를 AI로 구현해 요구사항을 즉시 검증
  • 노출률·인입률 계측 설계까지 AI로 빠르게 반영해 가설→구현→측정 루프를 단축
라이브 사이트 Admin (콘텐츠 편집)
03

산출물 & 역량

SRS

요구사항 정의

기능 요구사항을 우선순위·오너십과 함께 명세하고 개발/QA와 추적 연결.

RTM

추적 매트릭스

SRS ↔ 개발 TASK ↔ QA를 매핑해 커버리지와 누락을 한눈에.

QA

테스트 설계

통합테스트 + 크로스서피스 E2E, 네거티브·엣지케이스 중심.

DATA

지표 설계

Amplitude 이벤트 택소노미로 발급→적용→완료 퍼널 계측.

OPS

운영 자산

알림톡 13종 템플릿, 병원·사용자 매뉴얼, Decisions 로그.

AI

기획-디자인 파이프라인

노션 정책 → 스토리보드 → Token JSON → Figma 워크플로우 설계.

※ 계약사 수·발급량·전환율 등 실측 비즈니스 수치는 마스킹 정책에 따라 별도 자료로 제공합니다.
